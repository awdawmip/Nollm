# GRF8 Memory Quality

The deterministic fixture contains 10,000 evidence records, including six
categories, three-record revision chains, 17 partitions, 13 sessions, and
1,000 ground-truth queries. Queries cover direct facts, multi-hop scattered
facts, latest revisions, source-specific questions, timelines, conflicts,
decision rationales, and context reconstruction. Ranking functions use only
the query and evidence fields; `relevant_shard_ids` is used only by the
metric evaluator.

The fixed dataset digest is
`ba2cade4df7b3f27a68afa3f626532b76ee1e65b88823a96fad35046cda17449`.
All reported values are generated by
`experiments/grf/run_grf8_memory_quality_benchmark.py` on Windows.

N4 materializes current stitch endpoints only for cross-source queries, so it
removes the stitch misses while leaving ordinary revision queries unresolved.
N5 adds revision ordering across all query types. This is the explicit
ablation pair for without stitching (N3), without revision awareness (N4),
and the combined model (N5). N0, N1, and N2 provide the evidence-only, local
geometry, and coverage-only ablations; B0 through B4 are external lightweight
comparators.

The runner also computes context bytes, per-query latency, update latency, and
storage bytes from the same ranked results and fixture. On the fixed run, N5
used 212,297 context bytes, had 7.841 ms mean ranking latency, 0.164 ms
fixture-update latency, and 944,031 storage bytes.

The fixture has a remaining false-relation rate of 0.002 for N5 (two queries
per thousand), caused by a same-category hard negative reaching the five-item
context after the valid result. This is retained as an auditable failure class,
not suppressed. These results are limited to the documented deterministic
fixture and do not claim general product-wide superiority.
