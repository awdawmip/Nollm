# Core Capability Validation Report

The executable record is generated by `lab/nollm-lab/m1/run_core_capability_validation.py` into `CORE_CAPABILITY_VALIDATION.json`.

The validator uses `nollm-core` only. Its local Memory and Failing sinks implement the public Core Trace port without importing Access, Legacy GRF, OpenClaw, or product modules. Snapshot-port composition is exercised through atomic `export_state_bytes` and `import_state_bytes`; the owning `nollm-snapshot` package is validated independently.

Validated dimensions:

- semantic-blind MemoryAtom and addressed AtomHandle boundaries
- put/remove/replace/move/get/contains and explicit cell occupancy
- atomic batch, Bridge add/remove, canonical bytes, disk identity, close/reopen
- state export/import and independent clone behavior
- canonical 3 profile x 3 direction compiled templates
- direct, coverage, lateral, and Bridge Recall with deterministic budgets
- negative coordinates, mixed phase order, empty cells, exhausted budgets
- None/Memory/Failing Trace parity and Trace exclusion from state bytes
- stdlib-only Core dependency boundary and absence of semantic/global lookup APIs

The record is an active capability baseline bound to a concrete implementation HEAD. It is not a sealed or final declaration.
