# 写入时形成 Surface：内容预算与原生逐层使用

日期：2026-11-23（UTC+08）。本轮起点：`f9992a152326da487053b33103fc4bae3d75356c`。

## 1. 已落实的方向

用户要求 Surface 本身就是写入时提炼并保存的短内容。沿相邻、旋转缩放的蜂巢覆盖往下走，才展开条件、机制和详细证据。本轮在现有 Core 几何之上实现这条使用路径：上层短判断使用普通 MemoryStatement 与真实物理占用；入口层和可写层分开；同一物理入口下可以逐层改变当前观察位置；写入实际检查正文、条数及表层总量。

真实 LLM 负责提炼、区分命题和选择位置。Core 保持既有确定性几何；Access 检查内容容量并协调当前绑定。表层文字有自己的版本与来源，Surface 视图可以重建。查询过程读取已经存好的短正文，不临时从深层全文制造语义摘要。

## 2. 内容预算已经进入写入路径

可选配置是 `FIELD/access/content_budget.json`，由 AccessRuntime 打开时读取。没有配置的旧场保留原行为。每层可分别设置：

| 配置 | 检查对象 |
|---|---|
| `max_cell_atoms` | 单个物理格内当前 atom 数 |
| `max_cell_utf8_bytes` | 该格当前正文合计 UTF-8 字节 |
| `max_layer_cells` | 该物理层实际占用格数 |
| `max_layer_utf8_bytes` | 该物理层当前正文合计字节 |

试验配置：L−2 作为入口表层，最多16格、每格2条、每格128字节、整层2 KiB；L−1 条件层每格2条/512字节；原详细层 L0 每格2条/8192字节。下层全域不采用16格上限。数值是这份场的实验配置，后续依据真实使用调整。

`new` 和独立占用的 `revision_keep_history` 按新增正文计；`revision_current` 扣旧正文后计算新正文；`move` 计算原格减少与目标格增加，并检查实际当前载荷。`reuse` 仅保存同一命题的支持 Evidence 和绑定，不新增当前物理正文或 atom。原始材料、支持表达及历史版本保持可读。

容量检查在已有操作锁内、Core/binding 修改前执行。超量返回具体位置、指标、上限及前后数值，Host 可以重新提炼、在已观察的下层保存细节，或整理已有判断。先写短句再修订成长文同样受限。对已有超限场，允许超限指标不增的逐步减量整理；它仍显示为超限存量，不会被算作已达标。

现有1–100支撑压力继续是建议。高压力允许预算内的显式写入；容量超限需要改内容或位置。单条长度、单格条数和整层体量分别限制，分页不能使表层无限增长。

## 3. 入口层、可写层与当前观察位置

`encounter(surface_layers=..., layers=...)` 分别声明入口表层和局部可写层。对应 CLI 是 `--surface-layers` 与原 `--layers`。默认可存于 `FIELD/access/encounter.json`：

```json
{
  "surface_layers": [-2],
  "layers": [-2, -1, 0],
  "order": 0,
  "page_size": 8,
  "via": "downward",
  "steps": 1,
  "beam": 16,
  "limit": 20,
  "compact": true
}
```

首屏只显示 L−2 已存短正文。Host 选一个物理入口后，以当前格和相邻细层构成下一次局部观察。`--descend CELL_ID` 只接受本次已显示的真实 `coverage_down` 目标；`--ascend` 沿本次路径返回一层。`entry` 始终是原始唯一入口；`focus` 是当前观察位置；`focus_path` 和各表达的 `entry_path` 保留实际经过的几何路径。

`steps=1, via=downward` 让 Host 看见本次相邻层正文再决定去哪；`steps=0` 可只读当前格，直到显式下降才读下一格。一次下钻不重新从全场选择第二个入口。读到的事实可以在已声明可写层内维护；NEW、REVISE、REUSE 都遵守该范围。

Surface 的 Aggregation Order 继续表示可重建观察尺度，与上述物理层分开。当前小表层采用 Order 0，不必先聚合全部详细层。

## 4. 实际形成的三层候选场

Host 已读取原场当前判断和相关来源，检查现有覆盖后选择新语义与位置。原场23条详细判断、48份已有表达版本、几何地址及两条既有桥均保留。新增上层和条件层，没有复制详细正文，也没有增添桥。

| 物理层 | 当前表达 | 占用格 | 当前正文字节 |
|---|---:|---:|---:|
| L−2：完整短判断 | 8 | 8 | 398 |
| L−1：条件和使用关系 | 12 | 12 | 1,917 |
| L0：已有详细判断 | 23 | 21 | 22,242 |

表层8条一次完整返回，不截断；后续专项检查中，启用 `compact=true` 的首屏可见响应对象以无缩进 JSON 计为1,939字节（排除临时游标）。这不是首次读者的 CLI 输出文本计数。首屏的 Statement 读取只涉及这8条上层表达。选择上层后第一局部仅含 L−2/L−1；继续沿同一入口下降，才能取得 L0 内容。

枚举这份形成场的实际入口和相邻下降路径，23条原有详细正文全部逐字返回，其中19条能从多个上层入口进入。该检查复用原 Core 的向下采样关系，运行时没有摘要到子对象、对象到入口或独占父关系表。不同入口属于分别进行的场访问；单次会话仍保持一个根入口。

这是本次有限场的内容与路径验证。上层的概括是否足以帮助读者，还通过下一节的实际 LLM 使用检查。

## 5. 独立读者试用与形成反馈

一名未获得形成清单和物理映射的读者，从候选 Surface 自选入口，尝试两个开发理解问题；精度问题得到较完整解释，支持材料问题的首次路径遗漏了压力需求关系。

**精度问题：** 读者从“精确保持标签；量化模式允许关系变化”进入，下降后自然遇到 `precision-budget.v2`、`rational-geometry.v2` 和 `quantized-structure.v2`。正确区分现有 Core 的固定降位边界、Lab adaptive 的标签保持，以及允许结构差异的量化方案；同时读到当前量化默认12位、方案选择局部8位这两个不同状态。随后按已遇固定来源核对实际实现。

**支持材料问题：** 初次读者从“相遇共用读写，来源固定到提交”进入，找到当前绑定、支持和历史的区别，但该路径的中层没有明确连接支撑压力。形成反馈据此把原中层概括改为：

> current 表示当前绑定，源码依据固定到提交。reuse 只添支持证据，不新添物理材料，当前正文与压力需求不变；revision 切换当前正文并保留历史。

这条短判断引用已有 binding 与 pressure 两类证据，保留完整语义关系；没有追加上层入口或复制整份压力正文。条件层由1,907增加到1,917字节，表层仍为398字节。原读者按原入口回访，根局部的一层展开直接读到该新句，补齐压力需求解释。回访是对该反馈修订的复查，保留初次遗漏。

本地源码目录不是 Git 仓库，三次 `source` 回源均失败；随后通过 GitHub 连接器读取已遇到的相同固定提交与来源窗口。回源按辅助验证记录。开发过程中还加入了累计 `entry_path` 字段，因此本次试用不是冻结运行时的性能对比。

## 6. 本轮同时消除的重复读取

成熟场的首次 encounter 不再为了初始化额外打开 Core。Surface 按本页所需 handle 批量取得绑定及正文，避免每个候选各整读一次 `bindings.json`；请求结束后派生映射即可丢弃，新请求重新读取当前版本。物理候选在读取正文前分页。

候选场初始首屏记录为：Core状态读取2次、绑定读取8次。修正后各1次，首屏语义内容和顺序保持原样。现有后端仍将整个 Core 状态和绑定文件读入；本轮后续实测约35,405字节及10,854字节。正文显示有界与物理I/O有界是两件分别度量的事。

初次读者还发现局部响应有大量重复压力字段和来源列表。本轮新增可选 `compact=true`（CLI `--compact` / `--full-details`）：正文和可选对象完整保留，每条先返回一个固定来源、完整来源数和省略标志；`show ID` 仍可取回全部来源。可写格保留压力、权重、完整性及实际错误，详细中间量按需打开。后续专项检查遍历相同局部路径集，均以无缩进 JSON 计算可见对象并排除临时游标：`compact=false` 时最大21,918字节，`compact=true` 时最大14,821字节。这组数衡量省略重复 metadata 的效果，独立于首次读者包含缩进的 CLI 输出统计。深层正文和仍需的局部格本身占据这部分内容；本轮没有新增局部响应字节硬上限。后续局部存储应沿已知物理层/格实现。

## 7. 共享下层维护的一个实际方向问题

上层 `L−1(−11,9)` 的 `coverage_down` 以1/96命中下层 `L0(−9,13)`；后者的 `coverage_up` 仅包含 `L−1(−11,10)`、`L−1(−10,9)`、`L−1(−10,10)`，不包含原来的上层。

因此，下层改变后查找实际读者，需要按几何反演“谁的向下覆盖读到该格”。现有 `incoming_coverage` 反演的是支撑所用的向上覆盖，两个用途应分别表达。现有检查脚本复算这一见证；本轮保持原几何合同，尚未加入自动上层维护器。

更新时 Host 应检查实际受影响的短判断：原义仍成立则保留，条件改变则修订。会改变对象、适用范围、否定关系或当前状态的字词应保留在可发现的层次；普通支持不逐条占用表层，少见反例则应引起相应条件更新。
