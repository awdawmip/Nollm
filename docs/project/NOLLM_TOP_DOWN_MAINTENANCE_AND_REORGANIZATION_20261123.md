# 从上往下维护与跨模型重新组织

日期：2026-11-23（UTC+08）。研究基线：`5dd3c43c77127a60655d63360eb0a3c2a9d0babc`。

## 1. 本轮结论

用户提出两个相连的问题：是否需要知道一个细格被哪些上格覆盖，还是由上向下逐步巡查和纠正即可；后继 LLM 的分类习惯变化时，怎样重新组织已有记忆，同时保持事实可达。

建议将日常下钻、沿本次已走路径更新、从表层向下的维护巡查作为主流程。独立物理盘点处理声明范围内未遇到的当前材料。持久反向覆盖表不成为读取、写入或维护的必需条件；按需反查可以作为少量变化、明确需要定位影响范围时的局部加速。

上一轮把“反演真实向下读者”直接列为后续实现，隐含了每次细层变化都要立即找全相关上层的要求。本轮将其收窄：需要即时找全影响时，应查真实阅读关系；接受逐步巡查修订时，可以从表层往下完成维护。

跨模型适配先处理可读的短判断和中层条件。几何布局确实妨碍使用时，再调整物理位置。后继模型可以形成不同读法、修订旧理解或移动不变的表达；事实原文、当前判断、分类方式与几何位置分别处理。

本轮完成的是代价比较、真实复制场重组与当前方案更新。自动巡查调度、按需压力界面、多动作 Access 重组事务仍需实现；本轮没有引入永久反向关系表或替换 Core 几何。

## 2. 哪些操作实际需要“倒着走”

| 操作 | 当前依赖 | 本轮判断 |
|---|---|---|
| 已存 Surface 首屏 | 上层占用、当前绑定、上层正文 | 本场 Order 0 首屏没有 Coverage 计算 |
| 同一入口向下读取 | `coverage_down` | 无须先知道该细格的所有上层读者 |
| `ascend` 返回 | 临时 `focus_path` | 返回本次实际走过的路径，无须反求全部覆盖者 |
| NEW / REVISE / MOVE | 容量、现有 atom/绑定、目标格、持久化 | Access 写入本身不计算反向覆盖，也不自动改上层概括 |
| 找出所有可能受下层变更影响的概括 | 已枚举向下关系，或按需几何反查 | 属于维护方式选择 |
| 支撑压力 | `incoming_coverage`，即向上支撑关系的反演 | 这是现有压力计算，不等于“谁向下读到了这个事实” |

当前 `incoming_coverage` 反演的是 `coverage_up`。读关系的逆向查询应反演 `coverage_down`，两者不能互代。取消全局反向维护要求，并不意味着必须删除现有压力计算或沿会话路径返回的能力。

## 3. 实测：少量变化与批量变化的代价不同

基线场共43条当前表达、41个占用格，表层8格，声明层范围 L−2 至 L0。完整前向几何巡查保留空中间格，访问97个不同物理格，展开35个不同源格。只沿已占用中间格展开需要20次，但这项捷径只对当前形成场恰好读全，不能作为一般完整性条件。

### 3.1 同等语义材料下的定位成本

下面的前向方案先枚举实际向下关系，再在本次临时结果中筛选受改动影响的上层及相邻上下文；逆向方案按需生成局部候选，再调用同一个真实 `coverage_down` 核验。两者读取相同的待复核正文，均无持久反向表。

| 改动范围 | 前向展开次数 | 按需反查所需展开次数 | 前向冷缓存中位耗时 | 按需反查冷缓存中位耗时 | 两边准备的正文 |
|---|---:|---:|---:|---:|---:|
| 1个下层格 | 35 | 10 | 3.60 ms | 2.41 ms | 18条，7,308字节 |
| 3个相邻下层格 | 35 | 15 | 3.85 ms | 2.61 ms | 18条，7,308字节 |
| 全部21个下层格 | 35 | 44 | 4.46 ms | 5.50 ms | 43条，24,557字节 |

这一组来自本轮公开 API 复现。算法冷缓存使用公开物理缓存清理函数，并清理本实验的临时逆向包络；操作系统页缓存未清空，每次样本都重新打开 Core 和所需正文。中位数来自5次不带计数仪表的运行，未计入 LLM 阅读与判断时间。展开次数统计公开 down 请求；逆向冷启动另有3次公开 stencil 输入读取，时间已经计入。原始一次性内部 cache 观测与这次公开调用口径分别保存，均不作为运行时依赖。

对这份小场，少量更新时按需反查可以减少几何工作；一批下层几乎都变时，前向一次扫过更省。完整读取全部43条正文的前向巡查在这轮样本中约4.38–4.63 ms，读到24,557字节正文。实际维护的 LLM 阅读、理解和修改成本仍需另外计算。

当前固定 Core 的逆向候选可由公开 Q40 采样输入生成一个很小的整数包络，再以向下展开逐个确认。因此“每次局部反查”本身没有本场规模的维护成本；长期保存整张反向表才会增加关系存储、变换失效和更新协调。带不同中心扭转的 Lab 变换需要另行测量，不能直接沿用本轮固定 Core 的候选范围和耗时。

### 3.2 当前更直接的重复成本

在相同根入口 `(-2,1,1)`，一次当前统一 encounter 返回4条正文，但还为14个可写候选计算压力。实测包含8次 down 调用、108次 up 调用、15次 incoming-up 调用；4条 Statement 各读取两次。直接以相同入口和预算调用只读 recall，则是6次 down、0次 up/反查、4次正文读取。

这两者功能范围不同：统一 encounter 额外提供写入现场及压力，因此不能将全部差额当作无效工作。可改进之处是让共享读写现场的压力按实际需要展开，并复用本请求已经读取的 Statement。保留读写共用入口，不要求每次观察先给所有候选算完压力。

两种路径仍整读 Core状态35,405字节和绑定10,854字节。写入还会复制、序列化并保存当前 Core 状态，以及按动作更新绑定。降低同步反向维护要求不会自动消除这些全文件成本。

四份隔离复制场各执行一次 NEW、REUSE、原位修订和 MOVE，均未调用覆盖反查。NEW、修订、MOVE 都替换完整 Core 和 bindings 文件；REUSE 保存新支持正文并替换 bindings，Core文件不变。以本次 NEW 为例，224字节的新表达文件之外，还替换了35,657字节的 Core文件和11,085字节的绑定文件。这些是实际原子替换文件的长度，不是操作系统物理磁盘写入量。单次带仪表动作时间约1.74–2.41 ms，属于有限操作观察，不能作为写吞吐基准。

另一项通过现有 encounter 逐入口维护的试验用了56次 API 调用，其中47个局部页面；正文去重后24,557字节，实际重复返回102,770字节，可见对象无缩进 JSON 共349,022字节（排除临时游标）。这说明巡查应复用一次打开的状态和同轮正文，同时分别检查不同上层的概括。该试验承担完整路径观察，不与上表的纯计算准备耗时直接作性能比值。

### 3.3 成本模型

设一次有限巡查展开 D 个不同源格，实际向下关系有 E 条，准备给 Host 的正文为 B 字节。去重前向遍历的几何工作与 D 次展开及 E 次边处理相称；以现有96点内核计，未命中缓存的采样工作与 96D 相称。按需反查的相应成本取决于本批变化向上遇到的不同候选数 K，仍需付出真正受影响上下文的 B 字节与语义复核成本。

批量巡查可以把成本分摊到多次写入。逐次写入都立即全场巡查会重复支付 D 与 B。已知当前路径的局部更正可以先完成，其他共享上层在后续巡查或实际使用时重新遇到。

同轮可复用正文与几何计算；不同上层概括仍须分别与共享下层核对。不能因同一份正文已经读过，就跳过另一个上层的语义检查。

## 4. 自上而下维护成立的范围

日常问答可按语义选择分支，找到足够材料后结束。维护巡查需要自己的范围和完成条件：在确定版本的场、声明的入口和层范围内，沿真实关系检查所有计划分支，分批时保留公平的续行位置。

若巡查也依据旧概括决定“看起来不相关就跳过”，旧概括可以持续遮住其下的新内容。例如，假设未来量化默认值发生变化，旧上层还写着旧默认值，寻找新状态的读者可能一直跳过它。该例是假设，当前实现的默认值没有在本轮修改。

完整性需要分别记录：

1. **正常可见通路。** 每层有足够的完整短判断，读者能据此决定下一步。
2. **声明范围内的几何可达。** 已完成该范围的真实向下展开，必要时穿过空中间格。
3. **当前物理存量。** 用 Core 占用与当前绑定独立盘点，与完整巡查结果比较。

空中间格不代表更细层没有材料。`check_layered_surface.py` 原有占用格下钻用于上一轮形成场的实际短判断通路验证；本轮的完整前向复制场试验穿过空中间格，不把未检查完或缺中间概括直接记为几何孤儿。

盘点只回答“哪些当前物理占用尚未从这些入口遇到”，后续由 Host 读材料、补概括或重组局部。它不生成主题、词语或模型名到事实的查询目录。仅附属于现有占用的支持表达、已退出当前绑定的旧版本、已捕获尚未放置的材料，分别计量；`revision_keep_history` 若保留旧物理 atom 及其当前绑定，那份仍占用的材料继续纳入盘点。

对于一份有限快照，如果声明入口全部展开至指定细层且没有跳过目标，每个在该范围内存在向下路径的占用都能被枚举到。任意模型在固定小预算下选对分支，则还取决于表层表达、任务和模型理解；几何枚举本身不能提供这个语义保证。

## 5. 后继模型重新组织：实际复制场结果

本轮没有更换模型家族；这是已有读者的设计挑战及受控复制场试验，不称为新盲测或跨厂商性能比较。

### 5.1 先改短概括，原详细路径完全保留

原表层“相遇共用读写，来源固定到提交。”被另一个 Host 视角改为：

> 追加支持保正文，修订保历史；原文可回溯。

新句60 UTF-8字节，原位保存为新版本。两种表述关注角度不同。实际回读确认23条原详细判断的全部已枚举向下路径不变，旧概括仍可精确打开且 `current=false`，68份原有 Statement 文件字节不变。

这展示了后继模型可以更改入口的表达方式，保持原事实和实际几何关系。它没有单独证明新的措辞对所有读者更优。

### 5.2 移动事实：全局可达仍然可能掩盖旧入口损失

另一复制分支把 `nollm.binding.v3` 从 `L0(1,−1)` 移至实际观察到的 `L0(3,−1)`，使状态后果靠近操作说明。完整正文、来源与表达身份保持原样。

| 表层入口 | 移动前 | 移动后 |
|---|---:|---:|
| 正文、绑定、几何恢复 `L−2(0,0)` | 可达 | 失去该事实 |
| 相遇共用读写 `L−2(1,1)` | 可达 | 仍可达 |
| 运行时、工作场与源码 `L−2(2,1)` | 不可达 | 新增可达 |

移动前后仍然是23条详细判断全部可达，当前孤儿为0，该事实可达根数仍为2，原68份证据仍在。然而根集合已经改变。只比较总数、孤儿数或证据是否保存，会遗漏原入口的使用退化。

因此这项 MOVE 保留为待继续处理的实验候选，没有应用到活跃场。它说明重新组织应检查具体新旧入口及相关任务，Host 再决定旧读法仍应保留、应修订还是可以退掉。不同角度可以并存，确已无用的旧分类也可以退出，不要求永久保存所有历史分类。

### 5.3 事实身份与组织方式

当前可以使用 NEW 增加新的有意义短判断，使用 revision_current 改同一判断并保留旧版本，使用 MOVE 保留不变表达及绑定而改变位置。REUSE 只增加支持表达，不形成第二个可见入口；同一 statement ID 也不能同时绑定多个物理 handle。

多个上层读法共享下层，优先通过真实重叠覆盖实现。需要改变实际关系时，可以调整中层或位置；Stitch 是明确的格级桥，只在允许桥的传播模式中生效。当前默认 `downward` 不会因为新增一条桥就自动继续走它。桥的端点锚定格，MOVE 也不会使桥自动跟随事实。

模型偏好变化不自动证明旧事实错误。改分类时保留来源；若对命题本身有异议，依据证据形成修订或不同命题，分别说明条件与理由。普通内容可以按后继模型的使用经验重组，无须每种模型复制一份完整场。

## 6. 写入和重组应怎样形成可读路径

写入可以复用本次从表层走下来的 `focus_path`，不必先枚举一个细格的全部上层。新事实放置后，按实际阅读方向回读，确认当前组织确实能把读者带到正文。上层含义被改变时，先处理本次已经读到的相关概括；其余共享上层交给后续巡查。

有一个当前代码细节需要补齐：`_placement_cells()` 也提供向当前格输送向上支撑的候选，这些候选不一定在当前格的向下覆盖里。本轮原生见证是上层 `L−2(0,−2)` 与下层 `L−1(−2,−2)`：下格向上支撑该上格，权重683/65536，但上格向下不命中该下格。出现在可写候选中，不能直接当作本次入口已经连通。

对分类适配，先形成或修订上/中层短判断，并从新的入口读回原详细表达。实际要 MOVE 时，比较这次需要保留的旧读法与新读法。若要确认声明范围内所有旧入口原有的向下可达关系未丢失，可用一次完整前向对比；相关读法和任务是否仍然可用，还需回读核对，不需要常驻反向表。若明确允许某些旧分类退休，记录这个选择并检查它还承载的其他事实。

多步重组存在当前实现边界：Access 目前协调一次 Core 动作和绑定更新，对普通异常回滚；尚无跨多条 NEW/MOVE/REVISE、入口配置和多文件的统一提交。表层满额时“先增加新路、再退旧路”也可能触碰中间容量，尽管最终布局合法。后续可在现有 Access 内提供按最终占用检查的小型重组批次；普通异常回滚和跨文件崩溃原子性需分别实现。

## 7. 当前优化顺序

按本轮证据，优先推进：

- 有范围、可续行的前向巡查，复用一次打开的状态/绑定和本轮正文；物理存量盘点单列。
- 同一相遇中的压力按需展开，避免每次读取都重算全部候选；重复 Statement 读取在请求内复用。
- 将已有原位修订、MOVE、退旧占用接成清楚的局部重组动作，返回实际新旧通路结果。
- 持久化按已知层/格局部读取和写入；这项工作同时影响取数和放置。

按需 inverse-down 保留为可选加速，不是这些工作的前置条件。实际是否值得采用，取决于变化稀疏程度、变换合同、已有缓存与语义复核材料量。
