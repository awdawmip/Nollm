# Nollm 相邻层 8 位覆盖、采样与容量方案

日期：2026-11-23。代码审查基线：`d6a3d4c39aec4df56133a4c70bc081752d5ba5a4`。本轮交付为设计方案与一个可复算的单位探针；通用归一化执行器、分页存储及容量基准列为实施项。现有 `quantized` 函数默认仍为 12，本方案采纳用户明确接受的 **8 个局部二进小数位**，不把先前 12 位建议继续作为目标约束。

**同日后续修订：** 用户指出首层 Surface 本身应是存入上层格的短缩影，细节沿非树蜂巢逐层展开。容量实施顺序以[写入时形成 Surface 的研究](NOLLM_STORED_SURFACE_FORMATION_20261123.md)为准：先完成语义分层与表层内容预算，再让局部存储和分页服务这个结构。下文的 p8/96、尺度探针与全量 I/O 审计保留；“局部持久化优先”的组织前提不再作为当前方案。固定原版本见提交 `8bb8f8059900f85a21bcd5028e20244823d664db`。

## 1. 方案决定

**计算仅处理相邻物理层；局部小数精度定为 8 位；每源格继续使用 96 个等面积样本；覆盖产生的偶发缺项与增项直接成为工作结构。完整整数格地址、材料计数和原文容量独立保留。**

容量扩展首先解决按几何地址的局部存储和分页，复用现有层间尺度关系。正常读写只访问本次需要的格与正文；不用随着全库数据量增加而提高小数精度，也不用因全库变大就减少每个被访问格的采样数。

| 对象 | 本方案选择 | 控制的量 |
|---|---|---|
| 单次覆盖跨度 | `abs(target_layer-source.layer)==1` | 只建立上/下相邻层关系 |
| 局部数值分辨率 | `fractional_bits=8` | 归一化后的中间长度步长为 1/256 格尺度 |
| 每格采样数 | `sample_count=96` | 96 个等面积小三角形的质心归属 |
| 最小保留命中 | 1 | 接受实际量化产生的关系，不额外删小权重边 |
| 份额 | `hits/96` | 所选结构下精确的材料分配份额 |
| 格地址与材料数 | 完整整数 | 寻址范围、占用数量与累计支撑 |
| 输出 | 末端 Q16 与 1–100 分 | 显示和接口兼容，不回流近似内部计算 |
| 数据存放 | 几何地址分区、页、格内占用 | 扩容与局部 I/O |

这里的 8 位不是 float8、整数总字宽或 256 条记录上限。单源命中数是 0..96，97 个值本身可用 7 比特表达；材料总数和坐标不受这个范围限制。

## 2. 相邻层与下层加密

### 2.1 先前实验已经只算相邻层

`rational_coverage.py` 明确要求层差为 1，既有实验始终调用 1→0 或 0→1。此前 `depth=1/2/3/5` 是源侧与目标逆侧合计的扭转段数，发生在同一对相邻层之间。它不是跨越的物理层数。多段扭转的探针可以保留为复杂几何输入，但不能以“跨五层”为由提高正常相邻覆盖的精度要求。

一个层对的精确相对关系写成：

\[
T_{s\to t}=F_t^{-1}\circ F_s,\qquad |t-s|=1.
\]

尽量预编译这个相对算子，精确消去共同外层变换，按本次相邻层局部参数计算。纯仿射的已有整数路径很廉价，继续复用；不为统一叫作 8 位而额外量化其系数。需要非线性量化时只做一次声明的固定精度递推。

### 2.2 下层密度自然增高，局部单位保持一致

现有默认物理 profile 的尺度为：

\[
s_L=\beta^{-L},\qquad \beta=2^{1/4}.
\]

每向细层一步，长度缩小为原来的 1/β，面积缩小为 1/√2，同一世界面积中的格密度乘 √2。

| 向细层增加 | 同一世界面积中的格密度倍率 |
|---:|---:|
| 1 层 | √2 ≈ 1.414 |
| 2 层 | 2 |
| 4 层 | 4 |
| 8 层 | 16 |
| 20 层 | 1,024 |

这是面积/密度比例，不是树状父子数量；实际覆盖仍由旋转、尺度、位置与采样共同产生多个目标。新增物理层不扩大单次覆盖跨度。Aggregation Order 是观察聚合阶，与物理层号分开。

有理 Lab 按所声明的正有理尺度执行，密度比对应其尺度平方；本方案不通过改默认角度或尺度来获取性能，也不把有理参数族等同于理想无理默认参数。

## 3. 8 位必须采用局部格单位

### 3.1 实际发现的缺口

当前有理量化核先消去共同世界平移，再按固定 `2**p` 量化世界中间量；它尚未把两层的共同长度单位归一化。因而如果把越来越细的层的绝对世界尺度直接交给它，同一个 p8 不再代表同样的格内分辨率。

本轮复用了冻结主组中的 `d2_medium_up`，八个源格、768 个标签，两侧各一段不同扭转，只共同改变世界长度单位。全部完整 Fraction 与 adaptive 结果逐项保持原标签。

| 两侧共同长度缩放 | 当前 p8 相对精确参照的标签变化 | 当前 p8 关系增删率 | 归一化后 |
|---:|---:|---:|---|
| 1 | 9 / 768 | 0 | 原 p8 结果 |
| 1/256 | 645 / 768 | 35/48 ≈ 72.92% | 768 标签逐项恢复原 p8 |
| 1/65536 | 696 / 768 | 18/19 ≈ 94.74% | 768 标签逐项恢复原 p8 |

这个探针定位的是计算单位问题。归一化后保留了原 p8 的九个允许差异，没有对它们认证或修复。它说明可以继续选 8 位，同时把单位处理写进执行合同。通用归一化和规范锚策略仍需按下述设计实施。

### 3.2 归一化合同

采用物理上确定的规范锚 O 和正长度单位 ℓ：

\[
H(x)=\frac{x-O}{\ell},\qquad F_i'=H\circ F_i.
\]

则：

\[
(F_t')^{-1}F_s'=F_t^{-1}H^{-1}HF_s=F_t^{-1}F_s.
\]

这里先改变表示单位，再以 p8 执行近似。对现有径向扭转，单位变换规则是：

| 参数 | 单位变换 |
|---|---|
| 仿射矩阵 M | M/ℓ |
| 仿射世界原点 o | (o−O)/ℓ |
| 局部坐标锚 | 保持原层格坐标 |
| 扭转中心 c | (c−O)/ℓ |
| 半径平方 R² | R²/ℓ² |
| 扭转强度 k | 保持不变 |

在 Rational Lab 中，ℓ 使用该层对声明的正有理长度单位；无需从任意仿射矩阵强行开平方提取尺度。默认 Core 已直接使用相邻层的相对固定矩阵，不必先构造 β^-L 的绝对世界坐标。任意剪切仍按完整仿射处理；标量单位归一化不把剪切当作径向相似变换。

低精度格网的相位也应固定：O 从物理源格或固定几何块的规范位置求得，不直接使用可能因 `reanchor()` 改变的表示原点。源仿射的物理格中心可由规范化后的仿射函数精确求取；最终地址沿用完整整数锚及既有半偶舍入规则。现有 Core 使用偶数整格锚来处理边界 tie，是可复用的实现依据。

### 3.3 大地址与小数位分别处理

保留：

\[
\text{目标坐标}=\text{完整整数锚}+\text{有界局部余量}.
\]

先用原精确整数系数计算整数锚和余量，再对局部中间量保留八位。不要先把矩阵系数压到八位再乘十亿量级地址，否则系数误差会被地址放大。共同巨大锚的抵消也应在量化前完成。

层更细时，世界单位中的一个 1/256 格会随之变小；层号与地址范围增长不会自动消耗这八个局部小数位。实际中间乘积的机器字宽仍需按系数范围选择，不能把 p8 理解为所有乘加都使用 8 位整数。

## 4. 采样数保持 96

### 4.1 算术精度与采样密度是不同变量

现有六个扇区每个细分为 n² 个等面积小三角形：

\[
M=6n^2.
\]

| n | 样本 M | 一个命中的份额 | 逐点工作量相对 96 |
|---:|---:|---:|---:|
| 2 | 24 | 4.167% | 25% |
| 3 | 54 | 1.852% | 56.25% |
| 4 | 96 | 1.042% | 100% |
| 6 | 216 | 0.463% | 225% |

这里的工作量是点数比例，不是端到端提速实测。改变 M 会改变关系的采样探测和份额粒度；降低 p 则改变同一批采样点的运算归属。1/256 的长度步长不能与 1/96 的份额直接比较来证明精度足够。

### 4.2 选择 96 的已有依据

既有 `run_bounded_approximate_coverage_calibration.py` 比较 54 与 96，代码选择 96，并以 54 的 TV p95 超过 5%、96 的 TV p95 不超过 5% 等条件作为选择检查。该早期实验先丢弃不足 2% 的关系并重归一化。本轮读取了选择代码，没有取得旧输出记录，也没有把这些条件伪装成新一次实测数值。

之后的 broad 校准固定 96，比较一个/两个命中的保留阈值；当前 Core 的 `MIN_HIT_COUNT=1`，有理 Lab 也保留所有命中。本轮 p8 数据同样固定 96，因此既有证据支持把 96 留作本方案基线。

上一轮两组相邻层 p8/96 的实测：

| 指标 | 主组 | 第二组 |
|---|---:|---:|
| 相对精确同样本的结构差异 | 1.051% | 1.305% |
| 等权源格平均份额 TV | 1.036% | 0.998% |
| 完全消失关系原有平均份额 | 0.03255% | 0.03798% |
| 有需求格显示压力 MAE | 0.543 分 | 0.472 分 |

这些数据支持用户接受 8 位的选择；新规范锚与单位执行器完成后，复用同一冻结输入重新记录其实际差异即可。96 点本身的连续面积估计误差与这里的算术误差分开。

### 4.3 何时再研究 54

先完成 p8 的局部单位和容量路径。当完整请求的主要成本确实落在逐点计算时，再在当前不删命中合同下比较 54/96，并用 216 作较密采样诊断。默认相邻仿射可以复用独立 polygon oracle；任意扭转的曲边不能直接交给该多边形 oracle。

比较份额 TV、漏失/误增质量、主导目标、压力与候选代价，而不是对不同点集逐标签比较。216 只是更密诊断参照。每种 M 都使用自己的 `hits/M`，不能只换偏移而继续除以 96。

本轮选择 **8 位 + 96 点**，不把减少样本数设为扩容前置条件。

## 5. 容量不由这八个小数位限定

### 5.1 当前寻址空间

半径 R 的轴向六边形格盘含：

\[
C(R)=1+3R(R+1).
\]

| 当前地址合同 | 半径 | 单层地址数 |
|---|---:|---:|
| 活动可写域 | 2^30−1 | 3,458,764,510,599,315,457 |
| 可表达存储域 | 2^31−1 | 13,835,058,048,839,712,769 |

现有物理层范围为 −64..64。默认 Access 写入策略仍为 L0，显式多层策略另行启用。单格的 8/32 是密度状态标签而非硬记录上限。以一格一条为纯地址例子，半径 18,257 的六边形格盘已容纳十亿条地址。

所以目前不需要先扩大坐标位宽或层号范围。数学地址数量也不是已经实测的磁盘或吞吐容量。

### 5.2 真正的容量变量

需要分别观察：全部原文与历史版本的字节量、当前占用原子数 N、非空格数 C、单格密度、单次实际访问格数 V、返回正文数 K、缓存页预算。

一个格有很多材料时，相同几何覆盖只需按格计算，压力使用该格材料量乘覆盖份额；无需对每条正文重复执行 96 点几何。读取正文则按本次 K 和分页预算进行。LLM 的语义形成与放置吞吐也是独立成本，增加格数不会自动完成语义整理。

当前 Access statement 正文与 Core Atom 载荷存在重复。若 V_s 表示保留 statement 版本数、平均正文 b 字节，则当前正文基础量约为：

\[
D_{\rm body}\approx (N+V_s)b.
\]

只作为容量算术例子，设 V_s=N、b=1,024 字节：

| 当前记录数 | Core 正文基础量 | Core + statement 正文基础量 |
|---:|---:|---:|
| 100 万 | 1.024 GB | 2.048 GB |
| 1 亿 | 102.4 GB | 204.8 GB |
| 10 亿 | 1.024 TB | 2.048 TB |

单位为十进制 GB/TB；尚未计入原始 Evidence、来源引用、ID、绑定、JSON、文件系统元数据、临时提交与更多历史。容量最终按真实材料的平均字节数计算。分页是第一步，正文去重可以独立推进，不把 Core 载荷合同改造塞入首轮分页任务。

## 6. 当前实际瓶颈

下表来自基线源码审查，不是海量数据吞吐实测。

| 路径 | 当前行为 | 随规模增长的部分 |
|---|---|---|
| Core 打开 | 整读/解码 current_state.json | 所有当前 Atom 与正文 |
| Core 单次 batch | 复制全部格字典，排序、编码、整文件写入 | 整个当前状态 |
| Access 写操作 | 操作前导出全部 Core 与 bindings 作为回滚状态 | 全量快照；只改底层文件布局仍无法消除 |
| 绑定查询/写入 | 少量 handle 查询也全读绑定表；写入全排序替换 | 所有当前 bindings |
| Surface 缓存查询 | 先遍历排序全部占用格，再检查缓存 | 非空格总数 |
| Surface 分页/预览 | 全 records 过滤后截页；先读来源正文再截预览 | 页面之外的记录与正文 |
| 密格召回 | 先枚举格内全部 Atom，最终再截 max_results | 同格全部材料 |

固定参数大小、剩余扭转段数 d 时，本次覆盖工作量约为 `96 × V × (d+1)`。当前全状态 I/O 和编码还额外依赖 N 与全部状态字节数。只算相邻层并不会自动消除这项全库成本。

Lab 的 `evaluate_rational_pressure()` 会遍历调用者提供的整个下层库存；容量版调用必须先由实际几何确定本次来源范围，不能把全库都作为一次局部压力输入。当前 Access 压力已有局部 incoming 计算可复用，但其至多九候选结论仅针对默认固定仿射核。任意非线性层对需要自己的几何包络；未读全仍保持未知。

## 7. 容量扩展设计

### 7.1 按已有几何地址直接分区

复用已有 `GeometryAddress.partition_id(width=64)`。完整物理分区键包含 profile、chart、layer、phase，以及 `floor(q/64), floor(r/64)`。它只是物理存放方式，不改变六边形格及覆盖关系。

分区内部按 `(q,r,local_atom_id)` 分页，空格不分配材料，密格可使用多个页。不能把整个 64×64 分区再做成一份需要全量重写的大 JSON。

原文文件按已指定 ID 直接定位的现有机制可以继续保留。将来要打包小文件时，仍保留完整正文、历史版本和回源身份。

### 7.2 Core 与 binding 使用一次局部事务

put/remove 触及一个格，move 触及来源和目标格；对应 binding 在同一事务中更新。采用可替换的物理存储实现，原子提交和回滚覆盖本次记录或页。删除当前“每次写之前导出全场”的做法，全量导出改为明确请求。

这里需要的索引只用于已知几何地址、handle 或正文 ID 的物理定位。上下关系继续从几何计算，不保存对象间关系表、关键词入口或全局反向关系桥。

### 7.3 在读取正文之前应用预算

当前同一个格的 Atom 共用该格 score/path，最终按 `(-score, cell_key, local_atom_id)` 排序。若全局只返回 K 条，每个访问格最多贡献 K 条。因此存储层可先取各格按 local ID 排序的前 K 个候选，再确定全局 K 个 handle，最后读取正文。格内计数用于报告仍有未展示材料。

Surface 同样先确定本页几何格、再取有限预览 handle、最后读其正文；游标从有序键定位后续页，不全表过滤后截取。

格内溢出页仍属于原格。材料向邻格或下层迁移涉及语义放置，应由 LLM 决定；压力作为参考，不因密度高自动搬迁原文或禁止同层写入。

### 7.4 Surface 摘要按几何影响局部更新

保留覆盖质量、舍入和多目标汇聚定义，局部更新实际受影响的几何摘要。Aggregation Order 继续只承担观察聚合，不等同于新增物理层。

当前 Surface 对来源物理格与 native_count 有去重语义。同一来源经过多条覆盖路径汇聚时，不能简单相加下级 distinct count。实现时保留这一语义，或对更廉价的可加质量另设清楚的字段；不把两者混称。摘要与缓存可从几何占用重建，不成为外部对象关系索引。

### 7.5 扩容后的成本目标

\[
\text{磁盘规模}\propto\text{全部保留材料};
\]

\[
\text{普通请求工作量}\approx
\text{访问格的覆盖}+\text{实际读取页}+\text{最终返回正文}.
\]

常驻内存按页缓存、几何核缓存和本次结果设预算。远处增加无关材料时，固定局部请求不应随之加载更多正文或重写更大的当前状态。全库导出和真正全场几何变更按其实际范围执行。

## 8. 实施顺序与验收

几何线与容量线可以独立推进，然后在同一相邻层任务中整合。无需先建设分布式服务或额外控制平台。

| 工作项 | 具体变化 | 实际验收 |
|---|---|---|
| 局部 p8 | 声明长度单位、规范锚、整数地址/余量分离；保留 96 点；新配置明确版本 | 共同换单位、共同大锚、表示换锚不改变该配置的量化结果；相同输入可回放；所有96命中完整分配；冻结输入报告实际加权差异 |
| 局部持久化 | Core 与 bindings 同时改为按页局部事务；冷启动按需加载；全导出独立 | 旧材料、版本、handle与位置可回读；普通写只改有关页；事务失败不留下半个绑定更新 |
| 真正分页 | 每格先取有限handle，最后读正文；Surface页和binding查询不全扫 | 固定局部布局与预算，增加远处库存后触及页数/解码正文量基本不变；密格返回K条不遍历其全部正文 |
| 几何摘要 | 局部失效/更新影响范围，保留质量与来源去重含义 | 对固定几何与同一预算，分页结果、质量和去重计数与参照一致 |
| 采样再评估 | 确实由逐点计算主导后再比较54/96 | 统一min_hit=1与各自hits/M，比较完整成本、份额、压力和候选代价后选择 |

容量验证应同时使用稀疏远处分布与单格集中分布，记录实际页数、读写字节、正文解码数、峰值内存和延迟。规模取可运行且能区分全扫与局部路径的库存，不把未经运行的百万/亿级容量说成已经验证。

当前 Core 的默认 profile 与现有量化路径具有已保存历史合同。实施新局部单位配置时记录其实际精度/单位/样本数；按用户选择把新配置设为 p8，而不是静默改变旧结果的意义。
