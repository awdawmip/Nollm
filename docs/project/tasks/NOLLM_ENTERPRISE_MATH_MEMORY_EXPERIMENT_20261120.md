## 1. 要得到什么

做出一个大模型能够实际使用的、精简的外部研究记忆原型：理解和保存项目材料，连接公式、定义、定理、适用条件、证明思路和研究路线，使后续模型无需再次注入全部背景，也能找到材料、判断怎样复用、沿联系继续研究。

用户已将此前“收集架构理念、理解现状”的任务扩展为**理解之后继续开发**。理解材料为当前实现选择服务，交付包含可运行代码、实际模型使用和效果记录。理解报告、架构图、接口声明或模拟回答不能单独完成本任务。

用户提到的相关项目已核对为 **AOCI-CODE (`aoci-spec/aoci-code`)**，仓库已有 [AOCI 对照及实跑说明](../../../lab/nollm-lab/repository_memory/AOCI_COMPARISON.md)。借鉴重点是保存模型对项目形成的有证据理解、在后续工作中复用、来源变化后修订、必要时回到原文。Nollm 的几何组织和原生导航按其自身活动架构发展。

### 用户明确的实施要求

这是用于其他项目内部的试验组件，不是对外服务。**不要写任何防御性代码，不做无谓的验证、哈希或自证工程。** 不新增鉴权体系、签名/回执链、内部调用反复校验、泛化重试与降级框架、防御性全库扫描或泛化容错层。代码可以公开，直接在该实验分支开发和提交。正常资料读取和导入范围由实际任务决定。

采用普通函数、直接数据结构和现有运行时；普通错误直接暴露，按实际阻碍修复。保留定理的前提、公式、来源及更正关系，是记忆产品的功能内容；用真实使用检查查找和复用是否正确，是本任务的功能验收。这些工作不需要包装成防御性验证器。

复用现有 Git 版本和原生持久化即可，不为本实验新增内容哈希或完整性证明层。历史迁移的字节校验、几何核验收、Provider Live、旧声明检查器各有原范围，不能变成这个 Host/适配实验的全套前置流程。涉及的旧测试按实际行为变化调整，未触及的子系统不重跑历史全套。新增代码的目标是有用、直接、易于继续修改。

## 3. 理解如何支持开发

保留一份能解释当前改动的简短工作理解：要解决的问题、相关设计选择及理由、实际调用路径、已知差异、关键来源。复用已有项目缩影，必要时纠正；无需重建百科或先穷尽项目历史。

用普通文件阅读、现有搜索和实际运行建立初始理解，随后让记忆原型帮助维护理解，并以原文和真实行为纠正它。这样可以逐步自举：最初的开发不依赖一个已经完善的 Nollm，也不把系统自己的摘要当作唯一依据。

当前活动架构中影响本任务的区别：真实 LLM/Host 负责语义形成与选择；Core 负责确定性几何；物理层、聚合观察阶和语义粒度分别处理；原生导航在 Surface 上逐步观察并选择一个最终物理入口，再通过原生局部关系展开。几何邻近和召回分数本身不证明数学蕴涵。

使用外部关键词、向量或关系图辅助的路径可以做比较，结果按实际机制说明。原生路径不能先在外部选好对象，再把其坐标交给 Core 并称为原生发现。精确读取已知来源是正常回源功能。

跨线连接也可以作为有证据的语言判断被记住；由原生组织支持以后再次找到它。不要为实现连接而把 EM 的定理类型或领域规则硬编码进 Core，也不要另建一个成为原生正确性依赖的语义索引。能力缺口用具体试验定位，允许在当前授权范围内改进 Host、Access 和相关实现。

内容中立意味着 LLM 判断新命题、复用、修订和当前变化量，不能按主观“是否值得记住”永久排除内容。来源中的假设、证明、有限计算和正式接纳分别沿用实际状态。

## 4. 原型应支持的实际工作

以下是产品能力和使用情景，执行者自主选择实现顺序、组织方式和研究方法。

**形成可继续使用的研究理解。** 从现有成果卡和必要原文中组织有意义的命题、关键公式、对象/参数域、承重前提、证明或实验出处及限制。复用已有字段，缺少的信息保留为具体未知。新材料可以直接进入工作记忆，研究者不需要为每项结果手填另一套表格。

**按当前问题取得恰当材料。** 真实模型能够从研究问题或已知公式/定理出发，观察记忆、进一步查询、展开命题及原始出处。默认返回足够判断下一步的内容，细节再按需展开；不能靠每次把整个库重新送入上下文完成演示。固定符号或 ID 的精确读取与开放关联查询都应有直接可用的调用方式。

**发现并解释跨线联系。** 给出哪一个结果可能帮助当前哪一步、对象怎样对应、已经符合哪些前提、还缺什么、是否存在明确不适用之处。保留方向、对应和来源。待核类比与已经核实的复用分别表达；发现缺少桥接命题或准确排除一次错误套用，也有价值。不能仅输出“相关”标签或相似度列表。

**保存修订并继续下一项研究。** 使用已有持久化保存语义理解与放置，后续会话重新打开即可使用。成果更新或模型发现错误联系时，可按需修订受影响的理解和连接，并能找到对应原文。按项目既有资产方式保存实际记忆，交代下一位执行者可访问的位置和加载方法；只在会话结束即丢失的临时目录留下文件不算交付。先支持手动触发的局部更新；不用为此开发后台监控或全库维护平台。

**便于真实 LLM 接入。** 复用现有 skill/CLI 或普通模块接口，把入口、参数、返回内容和继续展开的方式写清楚。当前 Codex 自身可以承担真实语义 Host：阅读、形成判断、观察 Surface、选择入口、回源和使用结果。不要求先上线独立模型服务、MCP、Web 控制台或训练小模型。

默认使用 TASK／知情综合研究场景验证跨线复用。未来用于 FREE A 时沿 EM 当时的来源规则提供适用视图；本次全成果知情试验不冒称盲选题效果，也不为未来所有角色预建权限框架。

## 5. 怎样验收和比较

验收材料来自真实执行，代码能被下一位执行者按说明运行。演示题和开发样例可以公开。先做开放开发与实际使用，不把严格盲测基础设施当作开发前提。

| 观察面 | 有效证据 |
|---|---|
| 模型可用性 | 真实模型通过交付入口完成材料进入记忆、查询、原文展开和保存，记录实际命令、关键输入输出及使用结论 |
| 跨线复用 | 在实际 EM 问题上找到可用依据并推进一个具体步骤，或说明确切桥接缺口/不适用条件；能回到两边相关来源 |
| 条件与公式保真 | 检查实际结果是否漏掉承重假设、混淆对象/参数域、误写公式、把相似关系升级为可用定理；直接修复当前路径中发现的问题 |
| 后续继续使用 | 不携带前次工作上下文的真实模型会话，通过交付入口和已保存记忆完成下一项任务；只重启进程仅说明持久化可用。对实际更正或更新只处理受影响内容，并说明旧结论如何被修订 |
| 上下文与维护收益 | 记录构建、模型形成/放置、查询展开、更新的实际时间和可取得的模型输入输出用量，展示省去了什么、增加了什么 |

使用同一批来源和同一主模型，把候选原型与普通来源检索／现有成果卡直接使用作对照。需要判断“整理内容”和“导航机制”分别贡献什么时，再让双方使用相同语义材料进行比较。若两路内容不同，直接说明差异，不能把额外整理的知识全归功于几何。

比较原生路径和词法等辅助路径时，各自报告真实使用。模型已读过答案的重复案例属于开放回归或开发诊断；若后续报告未见任务收益，使用未参与整理和调参的新任务及相应实际暴露范围。无需先建一套隔离认证系统。

效果记录包括成功复用、错误连接、漏召回、无法适用的原因和成本。拿不到完整 token 或费用数据时写明实际计量范围；不从截断文本长度推导完整账单。任务、案例数和扩展深度按需要解决的不确定性确定，不设置固定配额或预先许诺节省比例。

**可运行交付与效果优势分别判断。** 实际可用原型、源代码、使用方式和真实试验记录是交付内容；Nollm 是否带来净收益由结果决定。若某用途没有优势，保留可工作的原型和失败原因，指出值得继续的具体方向，不循环调参直到表面胜出，也不把负结果隐藏在平均分里。
