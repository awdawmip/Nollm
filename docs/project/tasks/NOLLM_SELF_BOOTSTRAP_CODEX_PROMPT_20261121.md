## 目标

把 Nollm 自身的结构、理念、真实实现、跨模块关系和已知失败形成可回源的工程理解，存进 Nollm 原生场。让不携带形成会话上下文的新开发会话利用它完成真实代码修改，再把修改造成的理解变化维护回场，让后续新会话据此继续另一项开发。

这是内部理论验证系统。删除本次实际使用路径上的防御性代码，直接使用受信任的普通函数和清楚的数据流。不要增加重复内部校验、运行时哈希自证、认证、签名、审计、回执或通用容灾框架。普通错误直接暴露；几何和来源含义、当前绑定、历史版本及必要原子写入用最短实现保留。

## 架构与维护

Host 负责语义形成、放置、修订和 Stitch 判断，Core 负责确定性几何及状态，Access 负责原文绑定与回源。关系的成立条件写在表达中，几何组织共同现场。保留单一最终物理入口，区分物理层与聚合阶。用真实邻接、Coverage 和可逆 Stitch，不另建外置关系索引作为原生正确性路径。

用当前源码、设计依据和行为结果纠正记忆。按开发后的 Git diff 和已有来源引用做局部维护；不要在每次 show/walk 时全仓扫描或重新哈希。`current` 仅表示场内绑定。源码版本、运行版本和表达版本分别说明。

优先完成当前有价值的开发闭环。源码搜索和直接回源正常可用，实际救援如实记录。无需先完整理解全仓、完成全面框架通用化、整理全部历史或训练新模型。

## 验收与交付

交付可运行代码、实际自身项目场、短启动入口、真实补丁和对应记忆维护。必须有新的模型会话使用记忆完成开发，并有另一新会话在代码与记忆更新之后完成依赖该变化的不同开发；单纯重启进程或复问同题不满足接续验收。

同资料比较直接来源、同内容平铺和原生关系模式。原生与平铺使用相同的理解正文、条件和来源；共同形成成本同时计入，几何放置、导航和维护另计。Source 的检索范围排除本轮新增理解场、平铺导出、答案及比较报告；各组不读取其他组结果。任务正确性、来源覆盖、失败、耗时和实际可见输入输出都照实保存。按实际 usage 与计费数据分别报告其覆盖的 token 和费用，未覆盖部分保持未知。代码迭代对照使用相同后续源码起点。

公开例题用于开发回归；未见任务在记忆和布局形成后另选，不把答案、期望补丁或目标坐标种进被测场。新的正常会话不带作者上下文；实际共享文件系统时如实说明实验隔离程度，不为此开发安全系统。

按具体改动运行必要的功能、安装和存储回归；旧测试若只锁定已删除防御要求，可据新实际行为调整。方法、阅读范围和实施顺序由你根据问题自主选择，不设条目或方法配额。

沿同一 PR 持续完成本任务，发布一个清楚的交付入口，区分已实现、已测、未完和收益尚未证明。不要停在架构总结或入库数量；最终要有可继续使用、可以被源码纠正的自举开发循环。
