# Nollm Architecture Amendment V3.11: LLM-Compiled Recall Lens Junction Growth

Date: 2026-07-17

Status: active implementation amendment

## Decision

A real Host LLM may compile a bounded conversation batch into complete Evidence-backed Statements and operation-local Recall Lenses. A Lens describes how a future reader might approach a fact and cites exact Capture basis spans. It is teaching material for one Dream operation, not a Topic, axis registry, query route, or persistent memory object.

```text
immutable Capture batch
  -> finite Locality Atlas
  -> one Dream Sculptor semantic operation
  -> Statements + operation-local Lenses + candidate selections
  -> Access validation
  -> Core geometry-only Junction solve
  -> one Statement / one Atom / one Junction Cell
```

## Semantic And Geometry Ownership

The LLM decides proposition boundaries, duplicate/revision/new/defer semantics, future Recall perspectives, and which supplied Localities are relevant. It never outputs `q/r` coordinates. Access builds a finite frozen Atlas from real occupied/boundary/frontier cells and validates basis spans, candidate IDs, budgets, action, and state fingerprint.

Core receives only geometry addresses and bounded policy. It computes boundary and Junction candidates from distance, occupancy, free faces, active radius, and stable tie-breaks. Core never receives Statement text, Lens text, future queries, topics, sources, or semantic scores.

## Formation Boundary

A complete standalone proposition is eligible even when short-lived. Weather, appointments, preferences, cancellations, and transient but complete observations are not filtered by predicted importance. `no_memory` is limited to empty/tool noise, no standalone proposition, or exact no-new-information cases. Relative time is resolved once from Capture reference time and timezone while the original expression remains in Capture.

## Growth And Recall Duality

Later facts execute a fresh Dream Sculptor operation against the current Atlas. They do not read prior Lenses. Natural boundary growth can make an earlier Junction fact reachable from different physical entries. Each observation still selects exactly one final entry, performs one Core Recall, and injects one bounded Locality. No multi-entry Recall or persisted fact-to-entry map is introduced.

## First Implementation Boundary

V3.11 stores one Statement as one Atom in one layer-0 Cell. It does not implement multi-cell footprints, contact markers, duplicated Atoms, automatic Bridge/Stitch, multi-layer semantic Placement, persistent Lens/Cortex stores, Topic/Entity indexes, vectors, embeddings, or graphs.
