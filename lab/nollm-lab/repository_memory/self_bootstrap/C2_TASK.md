# 项目记忆开发任务：补充同一判断的证据

## 需求

现在通用项目入口可以保存新判断及原位修订。实际项目维护中，Host 也会得到另一份表达和来源，判断它支持已有的同一事实。请让项目入口能够保存这种补充，而不重复放置一个新记忆，也不把已有的当前判断替换掉。

提供以下命令形式，正文仍从标准输入读取，引用继续使用已有来源参数：

```text
memory.py project --field FIELD save NEW_ID --reuse CURRENT_ID --repo REPO --rev REV --cite PATH#Lfirst-Llast
```

`--reuse` 与现有的 `--at`、`--revise` 是不同的保存选择。Host 明确决定“支持同一当前判断”，系统不自行根据正文相似度作这个语义决定。

## 实际行为

- 补充表达有自己的版本 ID、正文和固定来源，可用现有的精确查看及回源入口读取。
- 补充后原记忆的物理位置、占用、当前正文和已有连接保持原含义。正常浏览与召回继续表达当前判断，不能把同一事实显示成两个独立占用。
- 对任意精确版本显示的 `current` 应准确表示它是否是该记忆目前呈现的判断；“还可读取”不等于“当前呈现”。
- 后续仍可对该判断原位修订。旧判断与补充表达的原文和引用继续可以读取，新版作为当前判断被浏览及召回。
- 新功能在安装后的项目入口中可用；已有新建、修订、来源读取和 EM 入口保持可用。

使用已有 Core/Access 行为和简单的内部调用。不要增加另一个关系索引、相似度决定器或验证/证明框架。必要的错误直接暴露。

## 材料与执行范围

使用统一提供的 C1 源码与既有设计/测试。可以正常搜索和读取其中的源码，也可以自行创建测试用来源仓库与场。

各组按启动说明使用分配到的材料：Source 不读取本轮新增记忆或其导出；Flat 使用与 Native 相同正文、条件、版本和来源的平铺记忆；Native 先从提供的 Surface 入口观察并选择，允许在需要时回源或使用正常源码搜索，实际路径如实记录。

不读取独立判据、其他组输出、形成者分析或比较结果。不修改提供的记忆场；开发和测试写入自己的工作目录。这是共享文件系统中新上下文的开发比较，不是权限隔离试验。

## 交付

实现可审阅的补丁和针对实际行为的测试，运行受影响的回归。说明保存、当前状态和后续修订的实际结果，列出所使用的关键源码证据，以及发现和修复的失败。保留真实调用记录；不要把工具输出字节换算成未观察的完整 token 或账单。

无需运行无关全仓测试或发布远程提交。
