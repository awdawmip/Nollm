# 仓库记忆 skill 的架构和验证计划

目标是让接手者从一条待办找到少量可核实的工程判断，能打开原始证据，改完代码后也能给下一次接手留下仍然有效的判断。本实验从 `736e19c` 延续，面向有本地 Git 对象的仓库。样本、测试草案及打包内容只来自 Nollm 或测试临时仓库。

## 谁负责什么

| 层 | 输入和输出 | 约束 |
| --- | --- | --- |
| 宿主或作者 | 从任务、实现和测试提炼判断，选择是否修改、回源和重写说明 | 为实际读过的提交负责，一条判断可引用多个文件 |
| Git 与清单 | `repo_notes.py` 将提交解析为固定对象，对每条记录的全部路径比对普通文件类型和 blob | 清单是人工维护的知识资产。单写者、整批验证、临时文件替换。Git 负责留存旧版清单 |
| Lab 路由 | `task_recall.py` 只对当前说明打分，确定一个入口及一张确定性布局 | 机器在本地扫描新鲜说明，返回给模型的上下文有独立的上限。入口评分发生在宿主适配层 |
| 原生记忆 | `field_demo.py` 把正文和引用写入独立工作区，关闭后重开，从一个物理格按预算遍历 | Core 只接收坐标、原子和预算。Access 核对召回正文与绑定；返回的引用随原生语句一起恢复 |
| skill | `SKILL.md` 和统一命令入口，安装时携带 Core、Access 的 Python 源码及许可证 | 在另一个仓库可以离线运行，清单的位置和版本由调用者指定 |

### 一次查询如何执行

1. 解析目标提交，用 Git 树批量核对主证据和辅助证据。变更、删除或类型变化都会使整条说明退出候选集合。
2. 将任务、说明键、路径和正文分词，处理驼峰标识符和汉字相邻双字。按词的稀有程度加权，键、路径、正文的权重分别为 3、2、1；并列按键排序。无共同词就返回空结果，交给源码搜索。
3. 仓库首次遇到这组新鲜说明时，按键稳定排列。已放置的说明根据共享证据为六个相邻空格投票，无可用票时另起一处。布局独立于查询；修改清单或证据后，坐标可随之变化。
4. 首次构建用 Core 和 Access 写入临时目录，关闭后用目录改名一次发布。在后续查询中，直接打开同一场，通过原生绑定取得所选说明的坐标，从该入口执行一步侧向召回。默认最多三条，可设为一至七条。保留原生遍历返回的顺序。
5. 读者用键及证据序号精确打开对应 blob，并与当前工作树核对。跨语言术语不匹配、命中泛词、布局偶然邻接、清单缺少调用方，都需要读者回源判断。

场位于目标仓库的 Git 私有目录。目录版本标识布局及原生格式，内容摘要涵盖每条新鲜说明的键、正文、核阅提交和有序证据。新提交若只改了无关文件，可以复用同一场；改变说明正文或任一证据会重新选择场。每次命中仍需校验 Git、选入口、加载原生文件并核对返回的正文和引用。较大清单的首次写入及共享证据造成的稠密邻域仍值得单独测量。

## 实施和验收

| 阶段 | 可执行验收 |
| --- | --- |
| 基线核对 | 重放原有 4 个 Git 和原生场回归，用 `evaluate_reads.py` 单独复算六道阅读题的字节 |
| 工程闭环 | 测主证据和辅助证据变化、历史重读、失败批次、复核队列、准确 blob、无命中、结果上限、稳定入口及原生邻格 |
| 可移植交付 | 安装到独立目录，再移动目录；隔离 Python 环境中操作另一个临时 Git 仓库，完成记录、召回、精确回源、证据失效和历史读取 |
| 主要对照 | 对同一份固定源码、同一组任务，分别直接搜、读全景再搜、读原生召回结果再搜。每个格使用独立会话，每次输出交给相同的外部验收 |
| 改进复测 | 保留首轮输入和评分，用短视图重复测量，辨别序列化开销和入口质量 |
| 仓库验收 | 运行 Lab 集成测试、现有包回归及模块边界检查。实际候选改动留在试验副本 |

### 如何用结果做决定

先看改动的行为是否通过独立测试，再看是否找齐必要证据，以及找到证据花了多少上下文。按题保留明细，避免合计掩盖某一题退化。记录实际发送给参与者的题目、入口视图、搜索输出、回源片段；区分固定编码器下的文本 token、服务商报告的输入输出及缓存 token、首次建场耗时。服务商未提供的指标留空。

只有新鲜且足以支撑任务的说明才有机会节省回源。即使全景比较长，简单的符号搜索也可能更便宜。先用能复算的试改判断该把 skill 放在哪类任务上，再扩大到无显式符号的交接、需要解释设计理由的变更、跨版本的旧判断和更大的说明集合。同一批题上的改进仅作复测，跨任务泛化需要新题与重复试验。

## 主线反馈

Access 现在按一次 Core 遍历返回的一批 handle 读取绑定，在原顺序逐条核验正文。公开接口与持久化格式兼容。先前的 UTF-8 阻塞已通过合入维护分支的 OpenClaw 修复解决，两项文档检查已恢复。实验分支和主线从同一验收提交继续演进。后续优化可按同一基准分别检查首次使用、跨进程重复查询、原始证据变化和历史重放。[性能对照与复现](comparison/FIELD_PERFORMANCE.md)
