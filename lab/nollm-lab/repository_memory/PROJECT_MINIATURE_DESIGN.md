## 研究结论

Nollm 最值得落地的产品形态是：**一份可持续维护的项目缩影，加上让宿主模型使用它的 skill，底层直接复用原生 Core 与 Access。** 缩影的基本内容是有源码依据、可以独立理解的工程判断；几何位置、局部占用、上下覆盖和有限连接共同承载这些判断之间的关系。模型通过有限的观察页面进入一个局部，再回到准确原文继续推理或修改项目。

“架构就是缩影”意味着，保存下来的组织本身已经包含项目理解。新会话既能读到判断，也能借助结构发现需要一起考虑的其他判断。一个关于修订一致性的事实，可以同时参与“来源核验”和“状态更新”两个现场；它在存储中仍是一份事实。这里应保留的是项目的行为、约束、联系和设计取舍，而非只按文件名制作目录缩略图。[1][2]

现有工程已经具备可用基础。Core 实际支持旋转缩放后的多目标覆盖，Access 有带正文预览的 Surface 导航，实验分支已有可运行的 skill 与 Coverage CLI。当前缺口集中在语义内容、LLM 放置、默认导航路径和成本。六道等预算新题上，现有 Surface 流程完整答对 3 题，源码搜索和平面 AOCI 均完整答对 6 题。因此，几何机制可用与项目理解优势成立，需分别判断。[5][8][9]

本报告建议先在 Nollm 自身项目形成跨文件判断，接通现有原生观察与放置接口；当前第 0 层写入策略已经足以启动这项工作。多物理层同时承载语句可以随后扩展，不作为前期验证的前置条件。

## 一 项目精髓应当怎样表达

### 结构承载可继续使用的理解

源码提供事实依据。LLM 读过源码后，形成例如“新增支持证据不会自动替换当前正文”“地址可以表示的范围大于当前写入策略允许的范围”这样的判断。它们可以跨越多个文件，也可以从同一文件拆出多条。判断在场中的位置体现哪些内容值得共同观察，原文引用则使任何判断都能被复核、修订或放弃。

项目缩影应让后来者回答三个连续的问题：这个局部在做什么；改变它会触及哪些约束；哪些原文能验证这些判断。规模可以远小于完整代码，但必须保留足以支撑这些问题的关系。缩影是任务相关的关系保留表示；本报告不主张它与整个程序存在严格同构，也不主张压缩后能够替代执行、测试或源码。

### 模型与几何各自承担明确职责

LLM 判断一条内容是否值得记忆、是否重复、应修订哪条事实、与哪些已知判断有关，以及应放在哪里。Core 在接受具体操作后，确定性地计算地址、占位、覆盖、邻接、路径分数和预算。Access 处理语句、句柄与证据之间的绑定。这样，语言理解与几何计算分别由擅长它们的一侧承担。[2][3][4]

这里最重要的边界是语义放置。两个判断共享同一源码文件，可以成为模型考虑的线索；这不意味着程序应按共同文件数自动决定语义位置。AOCI 的职责说明、依赖信息和源码定位可以帮助模型理解工程，但其标签编号、对象 ID 和引用边不能直接被当作 Nollm 的完整语义组织。

### 几何关系表达共同现场

同层邻接适合形成紧密局部，上下覆盖允许同一内容参与不同尺度、不同边界的共同现场，有限 Bridge 或 Stitch 可以表达确有需要的较远联系。任何一种关系都不赋予内容真伪或权威性；是否成立仍要核对证据、适用条件和当前版本。

这种表达天然容纳重叠。文件夹通常要求选择一条主路径，而同一条工程判断可以同时被多个覆盖区域发现。具体布局也会产生额外关系和遗漏，因而布局质量要由实际任务检验。几何提供的是可计算的关系结构，语义有效性来自模型对内容和现场的组织。

### 与现有组织方法的分工

| 方法 | 主要组织依据 | 与项目缩影的关系 |
| --- | --- | --- |
| 目录与文档树 | 路径和父子层次 | 适合原文管理，跨职责判断可另有几何现场 |
| AOCI 工程说明 | 压缩后的对象、职责、引用及标签 | 帮助读懂代码和回源，可作为模型形成判断的材料 |
| 常见向量检索 | 查询与候选文本的相似度排序 | 直接找相似候选；Nollm 的原生展开依据已接受的场结构 |
| 显式知识图 | 记录的实体及关系边 | 擅长明确关系类型；Nollm 用几何占用和覆盖产生大量局部联系 |
| Nollm 原生场 | LLM 语义放置与确定性几何 | 在不同观察尺度下进入局部，让同一判断参与多个共同现场 |

多归属、压缩或可视化本身都不是 Nollm 独有。它值得验证的组合，是语义形成与放置、旋转尺度覆盖、单入口有界展开、证据回源和持久维护共同工作。几何关系适合产生邻近与覆盖联系；有明确名称和逻辑含义的工程关系，仍需由语句内容表达，不能只看坐标推断。[2]

## 二 旋转蜂巢的上下覆盖具体意味着什么

### 层号与尺度

当前默认 profile 的相邻网格旋转 22.5 度，粗细边长比为 2 的四次方根，面积比为根号 2。层号每增加 1，格子变细；coverage_up 前往层号减 1，coverage_down 前往层号加 1。网格既旋转又缩放，相邻层的格子不会逐个整齐嵌套。[2][3]

本次选取非原点位置 L0(2,−1)，直接调用当前生产 Coverage 核。一个源格向上实际命中三个粗格：

| 粗层目标 | 96 点命中数 | 原生 Q16 权重 | 原生份额 | 理想源面积份额约值 |
| --- | ---: | ---: | ---: | ---: |
| L−1(1,0) | 45 | 30,720 | 46.8750% | 45.6079% |
| L−1(2,−1) | 20 | 13,653 | 20.8328% | 21.8731% |
| L−1(2,0) | 31 | 21,163 | 32.2922% | 32.5190% |

表内生产权重与理想面积分别计算，不能混用。可复算探针输出两层世界坐标，供在仓库外绘制覆盖图。[3][10]

### 覆盖方向决定权重含义

理想情况下，一条方向边的份额等于“相交面积除以出发格面积”。从细格向粗格走，与从粗格向细格走，分母不同。当前生产核又分别在出发格取 96 个样本，转换为总和 65,536 的 Q16 权重，所以两个方向还会有各自的采样误差。

本例 S 到 A 的原生权重为 30,720，A 到 S 为 20,480。它们表达传播分配，不表示语义相关的概率、置信度或可信等级。本次复用已有 Lab 有理区间计算，观察到上行总变差约 0.0126711、下行约 0.0150456；两次请求均未漏掉正面积目标。这是这两个具体请求的结果，不能推广为所有位置均无遗漏。[3][10]

Surface 保存的成员下钻也应与反向 Coverage 区分。已有独立边界例中，细格向上有 683 的权重，对应粗格向下采样可以为零；Surface 仍能沿已保存的成员关系找到来源。完整枚举某窗口已登记的来源，应使用 Surface 成员；物理传播则遵循各自方向的核。[6][8]

### 空层也能承担真实传播

本次第二个实验走正式 Access capture 与 apply 接口，只在第 0 层写入两条实验语句，其余物理层没有 atom。原生召回返回了目标与 coverage_up、coverage_down 核序列；按原生核重放，可以得到以下得分一致的地址路径：

L0(2,−1) → L−1(2,−1) → L0(3,−3)

两条边的 Q16 权重分别为 13,653 和 2,731，连乘取整后的得分为 568，Access 返回了目标原文。中间粗格没有保存摘要或语句；它的几何位置已经能让两处占用发生联系。地址重放展示一条与原生结果相容的路径；若有并列路径，不断言它是唯一的内部路径。[4][10]

这说明第 0 层写入足以利用跨物理层关系。同预算两步 lateral 在此例中也能到达目标，因此本例验证的是跨层机制可用，而非跨层召回必然胜过横向召回。另一组混合核实验中，同层相邻格的最优路径反而是先上后下，得分 11,904，高于直接 lateral 的 10,922，表明覆盖路径实际参与了排序。

### 三种不同的层次

| 概念 | 实际含义 | 在项目缩影中的作用 |
| --- | --- | --- |
| 物理层 Physical Layer | 记忆地址及真实网格尺度 | 决定覆盖、邻接及实际写入位置 |
| 观察阶 Aggregation Order | 从现有占用派生的观察尺度 | 控制分页、窗口与逐层观察 |
| 语义粒度 | 一个判断讲多大范围的问题 | 由 LLM 根据任务和证据决定 |

这三者应独立。函数、模块、系统理念不必分别固定到某一物理层。把观察阶调高也没有新增一条摘要或改变记忆位置。本次仅两个原生 atom 的稀疏场，在观察阶 0 至 3 分别出现 2、5、9、12 个非空观察格，总质量保持不变。旋转覆盖会分流到多个窗口，因此更粗的观察尺度并不保证非空窗口数更少，也不能据此宣称对数级检索成本。[6][10]

## 三 对当前代码和既有实验的判断

### 可以直接复用的能力

当前 Core 与 Access 已有持久化几何场、原生上下和横向传播、有限 Bridge、单物理入口、当前语句绑定与证据回读。AccessSurfaceNavigator 已能提供存储语句预览、下钻、返回上层、请求更粗观察面、进入物理候选并明确选择入口。一般 Surface 格最多提供 3 条预览，每条最多 256 字符；这些是实际语句片段，不会自动成为更高层的语义总结。[4][5][6]

实验分支 coverage_cli.py 已经暴露 footprint、build、surface、recall，surface 路径没有 query 评分。其 skill 已包含相应说明。本次复用原版 CLI 的机械检查通过：可从真实预览选择已显示候选，跨进程逐次进入唯一物理入口，召回并核验 Git 证据；读取前后原生场状态不变。该检查没有测量模型的语义选择质量。[7][10]

### 默认链路仍需要调整

主线 task_recall 的常用路径先对正文、路径和 key 做词法评分，选出 note key，再取坐标进入原生邻域。其他实验还有依赖图路由、来源共用投票布局，以及 AOCI 标签坐标编码。这些都可作为工程工具或对照基线，但其关系发现有相当部分发生在几何场外。[11]

需要把“直接查源码”“平面工程索引”“Nollm 原生观场”写成清楚的使用模式。对于项目缩影，原生模式的入口应由模型观察场后决定；若先用对象索引选中所需文件，再把该文件的坐标交给 Core，得到的结果只能说明后续几何读取可用。

对整个实验分支也应作准确评价。self_study 已有真实的多覆盖、Surface 导航和独立会话实验，不能将这些工作笼统归为坐标包装。应继续沿用这些资产，重点改进内容粒度、语义放置和默认使用方式。[8][9]

### 既有结果划出了具体能力范围

44 份 Core 与 Access 源文件的试验，用七个上层入口表达 86 项作者预期职责关系。调整后的覆盖布局命中 74 项、额外命中 22 项、漏掉 12 项，精确率 77.1%，召回率 86.0%。它证明单份内容可以参与多个真实覆盖现场，也显示几何布局会有失配。该优化针对已写下的职责意图，不是未见任务上的语义质量证明。[8]

后续六道新题采用 18 个独立首答会话，同一批 44 份源码、同一可见预算，每题每组一次作答。结果如下：[9]

| 六题合计 | 直接搜索源码 | 平面 AOCI | Surface 后单入口召回 |
| --- | ---: | ---: | ---: |
| 完整答对 | 6 | 6 | 3 |
| 局部答对 | 0 | 0 | 3 |
| 命中作答要点 | 18/18 | 18/18 | 15/18 |
| 所需证据召回 | 12/12 | 12/12 | 9/12 |
| 可见输入及答案 token | 21,127 | 38,096 | 43,181 |

Surface 六次召回共返回 60 个文件次，其中 9 个是题目所需证据；宿主最终引用了这 9 个正确来源。三次缺口可以定位：一份文件排第 25，被前十上限截去；另外两份位于所选入口的两步范围之外。此前两道已知失分题的定向复测找到 4/4 证据，是另一组观察，不能与六题成绩合并。

这组实验支持在技术词和源码符号明确的任务上继续优先源码搜索。它没有否定共享上下文的表达能力；它要求下一步直接改善入口、布局、预算与预览，不能只增加全仓条目数。903 个对象的全仓持久化和回读证明了工程覆盖，未单独证明理解更深或导航更省。

## 四 推荐的产品架构

### 一个项目包与一个宿主入口

建议复用现有 nollm-repository-memory skill。skill 负责教正在工作的模型怎样形成判断、观察现场、选择入口、回源与维护记忆。原生运行时负责实际状态与确定性操作。目标项目保存已经接受的语义状态，使下一个会话能够接着使用同一份理解。

| 组成 | 保存或执行什么 | 建议复用 |
| --- | --- | --- |
| 原始证据 | 源码、协议、测试及明确 Git 版本 | Git blob 与现有回源工具 |
| 工程判断 | 可独立理解的内容、条件与证据引用 | MemoryStatement 与 StatementStore |
| 几何记忆场 | 已接受的坐标、占用、句柄绑定及必要连接 | CoreRuntime 与 AccessRuntime |
| 派生观察面 | 有界预览、窗口成员、分页与候选 | AccessSurfaceNavigator |
| Host skill | 语义形成、放置、观场选择及最终推理 | 现有 skill 与薄 CLI |
| 工程辅助工具 | 符号搜索、依赖提取、AOCI、版本差异 | 现有 facts、source、route 等 |

GitHub 适合存源码、版本依据和可恢复的已接受状态；实际导航与推理发生在运行时和宿主模型。初版可用 Python CLI，不必额外启动第二个 LLM 服务或常驻服务。以后适配 MCP，也只需改变传输方式，保持相同语义与几何职责。

### 真正需要持久保存的内容

项目包应保存独立判断、精确证据引用、当前与支持绑定、已接受的几何位置及必要操作结果。仅保存原始文件，再让新会话重新调用模型布置，不能保证恢复原来的理解。Surface 页、覆盖缓存和展示文本属于可以从接受状态派生的视图，删除后应不改变记忆含义。

Git 提交与 blob 可以确定记录所依据的源码版本。它们不能证明自然语言判断正确，也不能自动证明未提交工作树或运行中的部署状态与记录一致。证据变化后，应重读受影响的判断，再由模型决定保持、修订、拆分、移动或遗忘，而非按关键词全库重新排列。

### 形成和放置怎样衔接

模型沿项目真实入口、行为和测试读原文，形成有条件、有依据的独立判断。形成后，可以先 capture 保存内容，随后根据已有现场判断复用、修订、新放置或暂缓。观察到共享关系时，模型检查原生足迹与现场空位，选取能服务这些关系的位置。Core 只执行合法的几何操作。

例如，“增加支持证据不会替换当前正文”同时关系到来源核验和修订一致性。模型可以把这条判断放在两个局部均能触及的位置，并检查实际传播和预算下是否可达。若目前无法同时满足所有关系，可以保留局部失配，选择另一位置，或在确有依据时使用有限连接；无需把所有语义关系强行压成完美几何嵌入。

### 使用时的闭环

用户提出问题后，宿主读取有界 Surface 页面，理解预览，再决定放大、翻页或换观察尺度。到物理候选后明确选择一个入口，Core 根据实际核与预算展开，Access 解析命中的当前语句及引用，模型回源后回答或修改。每次结果保留入口、路径、预算和证据状态，便于知道答案依赖了什么。

已知精确符号的定位可以直接用源码工具。原生路径发现的证据不足时，应报告本次覆盖范围并继续必要的原文调查，不能把未返回解释为不存在，也不应把辅助工具找到的答案记为几何召回的胜利。

## 五 以 Nollm 自身构造项目缩影

### 首批内容采用跨文件判断

建议从下列已核对的判断种子开始。编号只用于报告说明，不充当查询到坐标的路由。实现路径基于当前主线，Core 与 Access 分别指 packages 下的两个原生包。[4][5][6][12]

| 判断种子 | 跨越的责任 | 主要回源位置 |
| --- | --- | --- |
| Capture 保存语句，几何放置是后续决定 | 内容形成与状态提交 | Access runtime 与 formation |
| 附加支持语句保留当前正文，切换正文需要修订 | 来源补强与版本变化 | Access handle_store 与 runtime |
| 几何命中先返回句柄，Access 再解析当前绑定并核对正文 | 传播与证据一致性 | Core recall 与 Access runtime |
| 缺绑定、缺原文、原文损坏和正文不一致具有不同含义 | 错误解释与证据使用 | Access runtime 与 statement_store |
| 状态条件失配时不暂存新语句，失败清理只针对本次新增内容 | 并发状态与写入原子性 | Access runtime 与 statement_store |
| 重复引句须消歧，可用左右上下文、出现次序或二者组合 | 引用定位与证据身份 | Access evidence_anchor |
| 活动 default_dream_v1 的单入口由 Access 检查，Core 通用结构不改变 Host 合同 | Host 合同与传播请求 | Access recall 与 Core recall |
| 路径分数保留最佳传播路径，数值不代表语义正确率 | 几何排序与模型推理 | Core recall 与 kernel_registry |
| 深度、前沿、层差与结果数量分别限制召回 | 预算配置与证据遗漏 | Core recall 与 Access recall |
| Surface 成员下钻与反向 Coverage 具有不同完整性含义 | 观察与物理传播 | Core surface 与方向探针 |
| 可表示的几何地址范围与当前语义可写范围不同 | 几何能力与写入合同 | Core geometry 与 Access write_policy |

这批内容将记忆粒度从“一文件一个职责”推进到“一个可继续使用的工程判断”。一条判断可以引用多个文件；一个文件也可以支持多条互不重复的判断。首批数量应由已核对内容决定，无需为达到整齐配额生成空泛说明。

### 两个能体现差异的现场

**附加证据后正文为何没有改变。** 这个问题需要共同观察支持绑定、当前正文、修订动作和跨存储一致性。按目录查找时，它们分散在不同实现中；项目缩影可以把这些判断组织为同一个可展开现场，使模型一开始就知道应同时核验哪些条件。

**增加 Coverage 步数后为何仍缺证据。** 这个问题需要入口、方向分派、路径得分、beam、层差、返回上限及 Surface 成员一起参与判断。把预算判断放在“入口选择”和“传播行为”都可发现的位置，能够直接利用多覆盖。是否产生实际收益，要看模型是否选对入口、关键关系是否进入返回预算，以及观察成本是否合理。

这两个现场适合作为演示和作者检查。后续质量比较仍应采用未参与写判断和调布局的新问题，分别记录原生命中、模型选择和回源贡献。

## 六 skill 与运行时需要怎样增量修改

### 优先完成同一条原生主路径

已有 Coverage CLI 足以演示固定场，其余改造宜在同一个工具中完成。优先把原生模式的 skill 入口改为观场选择，接入现成的返回上层、请求更粗观察面及完整物理候选动作。召回统一复用 Access 的原生入口接口，开放已有上下、横向和有限 Bridge 组合；查询语义不进入 Core 权重计算。[5][7]

CLI 当前通过从头重放选择历史恢复页面，且 recall 接受调用者另传坐标。固定不变的实验场可以直接使用。面向真实维护时，建议复用现有导航序列化，并在薄适配中把页面、所选入口和召回绑定到同一场状态；检测到场变化后重新观察。现有导航状态本身还没有场版本绑定；现有写入状态条件可用于提交阶段，不能自动保护这条读取链路。

原生 formation 与 FieldEncounter 已经提供形成及放置基础。应复用这些接口建立宿主无关的薄适配，把候选观察、LLM 决定和实际提交接起来。不能只自动生成说明后按 key 顺序铺格；那会保留运行时，却失去语义放置这一核心工作。[12]

### 先做当前写策略能够表达的关系

当前活动策略要求新语义位置在第 0 层。初版可在该层保存全部判断，使用空的粗层格产生共享上下文。这条路径不改变生产 Coverage，也已被本次正式 Access 实验验证。

若进一步让不同物理层直接承载语句，需要同时研究写入策略、Placement Contract、FieldEncounter 候选和 junction 的距离语义。现有 junction 距离要求同一物理平面，因此不能只删去 layer 等于 0 的校验。多层写入的内容意义仍由模型决定，不预设“函数、模块、理念”与层号的一一对应。[12][13]

### 明确暴露覆盖不足

当前预算标志不等于完备性证明。本次 beam 为 1 的实验漏掉已经放置的粗层内容，却返回 budget_exhausted 为 false；代码未将 beam 丢弃的全部分支计入该标志。产品应把实际返回数、可解释的截断及覆盖边界展示清楚，不能据单一布尔值宣称已经找全。[4][10]

预览也需要可用性改进。当前少量语句片段足以启动导航，但可能掩盖稀有关系或把长语句截断。先保留真实预览与完整原文入口，按真实任务改善选择与展示；只有另行形成并有证据支持的语义摘要，才可以作为新判断保存。观察窗口本身不自动拥有“总结正确”的含义。

## 七 优势成立的条件与适合的任务

| 任务形态 | 建议起点 | Nollm 应争取的具体收益 |
| --- | --- | --- |
| 已知函数名或错误字段 | 直接源码搜索 | 快速核验，形成可复用判断 |
| 初次理解陌生项目 | 项目缩影与原文入口 | 有界地进入行为和约束现场 |
| 跨模块改动与影响分析 | 原生场中的共享判断 | 发现不同目录中的共同约束 |
| 设计理由与历史取舍 | 版本化判断及证据 | 在新会话中继续已有理解 |
| 变更后复核 | Git 变化与受影响证据 | 局部修订判断和布局 |

最有希望的优势，是同一条判断被多个问题现场发现、观察尺度可调整、局部关联可在有界上下文中展开、答案可回到原文。这些机制在当前代码中有基础，但节省时间、token 或漏项的幅度仍应由任务验证。

代价主要来自三个方面。第一，优质判断与布局需要真实阅读，首次形成有成本。第二，几何可表达的局部重叠与任意工程关系不会自动完全一致，拥挤、长程联系和边界会造成失配。第三，Surface 分页、预览和多轮选择本身消耗上下文与调用时间。已知六题的失败应保留，作为后续对照。

下一轮验证应对齐问题、源码、可见输入和回源预算，纳入首次形成、维护、观察及实际答题成本；同时区分“几何上可达”“进了返回列表”“模型读到了”“最终回答正确”。这四个结果之间不能互相替代。需要同时保留明确符号题与跨职责题，避免只挑有利场景，也避免让词法定位任务代表全部目标。

## 八 向全局知识库扩展的方式

代码项目适合作为首个落地对象，因为源码版本、测试与变更影响较容易回查。验证过项目内的形成、导航、维护闭环之后，可以将同一套机制用于更广的知识集合。

全局知识仍需要明确的事实来源、适用范围、时间与授权规则。规范性入口按确定性规则加载，Nollm 场帮助发现相关知识和证据。几何相邻不会让旧规则重新有效，覆盖权重也不决定规则优先级。不同知识域可以保留各自来源和权限，模型在授权范围内组织可复用判断。

Git 可保存原文与版本化接受状态，派生观察面按需要建立。这样可以渐进接入已有知识，无需先搬动全部目录或重写所有来源。最有价值的迁移单位是一条能够被复用、能够被回源、具有明确适用条件的判断。

## 九 本轮交付及实施顺序

本轮完成了第一性原理与当前实现核对、既有实验复核、原生多层和空层中继实验、现有 Coverage CLI 的流程检查，以及本架构设计。实验直接使用当前原生包及已有 Lab 几何函数，没有重写 Coverage，没有更改生产样本数或写入策略。

建议按以下顺序实施，复用现有 experiment/repository-memory 分支：

1. 将本报告中的跨文件判断种子核成一份小型项目记忆，由真实 LLM 在原生现场中决定位置，保存已接受状态。
2. 把现有 skill 的项目缩影模式接到 Surface 与 FieldEncounter；统一单入口、原生核、回源和局部维护流程。
3. 用未参与布置的新任务检验发现质量与全部可见成本，保留现有六题原始结果，分别比较符号定位和共享约束任务。
4. 根据实际使用需要扩展多物理层写入、预览和预算反馈，再评估向更广知识库接入。

目前可以明确推进的是前两项的产品路线。几何机制、持久化和导航接口已有实际证据；下一批工作应把优势落实到判断内容与模型使用上。多层写入、普遍节省 token 或完整项目理解的提升，仍属于需要单独验收的能力。
