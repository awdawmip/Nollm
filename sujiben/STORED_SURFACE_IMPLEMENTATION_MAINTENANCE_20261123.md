## 预算与使用

`access/content_budget.json` 为 L−2 设置每格2条/128字节、整层16个占用格/2 KiB；L−1 每格2条/512字节；L0 每格2条/8192字节。新写、替换正文与移动都经过当前正文容量检查；支持 Evidence 和旧版本继续保存。现有支撑压力仍是建议，容量超限返回实际指标和上限。

`access/encounter.json` 设定入口层 `[-2]`、可写范围 `[-2,-1,0]`、Order 0、每页8格、`via=downward`、`steps=1`、beam 16、limit 20 和 `compact=true`。`descend` 只接受刚显示的相邻目标，`ascend` 按观察路径返回。根 `entry` 始终不变，`focus` 指示当前位置。完整使用命令见[速记本入口](README.md)。

当前首屏8条全部显示，未截断、无续页。按返回对象无缩进序列化并排除临时游标计，首屏1,939字节，实际局部路径集合的最大响应14,826字节。正文、JSON 与底层 I/O 分开计量。首屏 Statement 读取仅为8条上层正文，各1次；Core状态和bindings仍各全文件读1次，分别35,405与10,854字节。局部响应尚无独立总字节硬上限，按层/格持久化仍需实现。

## 实际读者反馈及修正

在发布前，未获得形成清单和坐标映射的独立读者从候选场 Surface 自选入口试用了两个问题。精度问题沿两层读到了精确标签、量化关系与当前默认值的区别，并按已遇固定来源复核实现。

支持材料问题第一次找到了当前绑定、reuse 和历史，却没有从该路径直接读到压力需求的关系。Host 据此修订候选场的一条中层概括：

> current 表示当前绑定，源码依据固定到提交。reuse 只添支持证据，不新添物理材料，当前正文与压力需求不变；revision 切换当前正文并保留历史。

原读者按原物理入口回访，直接遇到这条修正后的正文。此次回访确认修正有效，保留首次遗漏；它不是新一轮盲测。活跃场的首次上层/中层形成已经采用该修正正文，候选场的试用和修订过程保留在本记录与结果记录中，原活跃场的48份版本不受影响。

三次本地 `source` 命令因局部源码目录不是 Git 仓库而失败；随后通过 GitHub 连接器读取已遇相同固定提交和源码窗口。开发期间运行时也有变化，因此这些试用不作为冻结运行时性能对比。完整研究见[实现说明](../docs/project/NOLLM_STORED_SURFACE_IMPLEMENTATION_20261123.md)。
